# 兼容性与已知限制

## 支持范围与验证状态

当前面向 Windows PowerShell + Python 3.11+ + Codex CLI。macOS/Linux 尚未声明支持。表中的“待验证”不能作为已通过承诺。

| 项目 | 当前状态 | 说明 |
|---|---|---|
| Windows / Python 3.12.10 / Node 24.14.1 | 本地离线检查环境 | 测试隔离真实配置与凭据，实际计数见维护者本轮验证记录 |
| Windows / Python 3.11、3.12、3.13 / Node 24 | CI 已配置，云端待运行 | 工作流包括离线测试和按 HEAD 构建源码包 |
| macOS / Linux | 不支持承诺 | 凭据 helper 使用 Windows 当前用户加密 |
| Codex stdio MCP | 有模拟回归，真实宿主待验证 | 离线 stdio 测试模拟 provider，不等同实际外部任务 |
| Codex MCP Apps 面板 | 实际宿主待验证 | 必须分别记录桌面宿主版本与面板操作结果 |
| 外部 Responses provider | 按服务与模型逐项验证 | 本候选没有已验收的具体 provider 清单 |
| 仅 Chat Completions 的服务 | 不属于当前直接支持范围 | `/models` 成功不代表可以执行 Codex 工具任务 |
| Node + Chrome/Edge 网页读取 | 可选，真实浏览器待验证 | Node 需内置 WebSocket，并使用 README 所列固定安装路径 |

## 已知限制

- 依赖 Codex CLI 的命令、配置、事件和续聊接口；目前没有已验证的最低/最高 Codex 版本范围。更新 CLI 后应重跑真实验收。
- 并行任务共享指定工作区，工具不会自动创建 worktree、解决冲突或合并改动。写入任务须分配互不冲突的文件。
- 子任务思考强度当前固定为 `medium`；并发上限 1–8，待交付结果最多 30 条，应及时完整读取并确认。
- 工作区路径检查与角色沙箱不能代替所有工具的安全边界。允许 MCP/Skills 时要审查其文件和网络权限；环境变量过滤无法识别任意命名的秘密。
- 选定任务的代码、提示词与结果可能发送到所选 provider；本机加密存储保护本地密钥，不意味着外部服务看不到提交的数据。
- 不保证费用更低、速度更快或答案质量更高；目前没有受控对比基准。
- “保留记录”和“保存可续聊会话”作用不同；原生回退是一次性会话。配置变更或权限撤销可能使旧活动无法续聊。

## 如何增加已验证环境

按 [验收表](acceptance.md) 记录候选 commit、Windows/Python/Node/Codex/宿主版本、provider 协议与模型 ID、日期、操作和结果。先完成一次真实工具任务，再标记 provider 已验证。不要公开私有服务地址、凭据、私人任务全文或敏感日志。
